# 배포 가이드

실제 API 키를 넣고 돌려 보기까지의 순서입니다. 가장 빠른 길은 **Vercel + 관리형 PostgreSQL**이고, 직접 서버를 쓰면 **Docker Compose**로 띄웁니다.

## 0. 준비할 것

| 항목 | 어디서 | 메모 |
| --- | --- | --- |
| AI 키 | Anthropic Console, Google AI Studio, OpenAI Platform | 하나만 있어도 동작하지만, 세 모델 비교를 보려면 셋 다 |
| PostgreSQL | Neon, Supabase, Railway 등 또는 직접 설치 | `DATABASE_URL` 하나면 됨 |
| SMTP | Resend, Postmark, Gmail 앱 비밀번호 등 | 없으면 인증 메일이 안 나가서 부모가 아이 프로필을 못 만듦 |
| 관리자 토큰 | 직접 생성: `openssl rand -base64 32` | `/admin`, `pnpm smoke`, `pnpm usage`에 사용 |

환경변수 전체 목록은 `.env.example`에 있습니다. 운영에서 꼭 필요한 것:

```
ANTHROPIC_API_KEY=            # 셋 중 하나 이상
GOOGLE_GENERATIVE_AI_API_KEY=
OPENAI_API_KEY=
DATABASE_URL=postgres://...   # 운영에서는 필수 (없으면 시작하지 않음)
SMTP_URL=smtps://user:pass@smtp.example.com:465
MAIL_FROM="생각 먼저 AI <no-reply@yourdomain>"
APP_URL=https://yourdomain    # 메일 링크 기준 주소
ADMIN_TOKEN=                  # 길고 무작위한 값
```

## 1. Vercel (추천)

1. GitHub 저장소를 Vercel에 연결합니다. 프레임워크는 Next.js로 자동 인식됩니다.
2. Vercel 프로젝트 설정 → Environment Variables에 위 값을 넣습니다. `MOCK_AI`는 넣지 않습니다.
3. PostgreSQL은 Vercel Marketplace의 Neon/Supabase를 붙이거나 외부 URL을 `DATABASE_URL`로 넣습니다.
4. 배포합니다. 앱이 처음 DB에 붙을 때 `drizzle/`의 마이그레이션을 자동 적용합니다. (미리 적용하려면 로컬에서 `DATABASE_URL=... pnpm db:migrate`)
5. 확인:
   - `https://yourdomain/api/health` → `"ok": true`이고 `problems`가 비어 있어야 합니다.
   - 로컬에서 `APP_URL=https://yourdomain ADMIN_TOKEN=... pnpm smoke` → 실제 모델로 전체 파이프라인을 한 번 돌리고 단계별 결과·시간·토큰을 보여 줍니다.
   - `https://yourdomain/admin` → 관리자 토큰으로 들어가 호출 비용을 확인합니다.

주의: Vercel Hobby 플랜은 함수 실행 시간이 짧습니다. `/api/compare`(모델 2~3개 + 판정)와 `/api/admin/smoke`는 길어질 수 있으니 느리면 Pro로 올리거나 모델을 가벼운 것으로 둡니다(기본값이 가장 가벼운 모델입니다).

## 2. Docker Compose (단일 서버)

```bash
cp .env.example .env.production   # 값 채우기. DATABASE_URL은 compose가 덮어씀
docker compose up -d --build
curl -s localhost:3000/api/health
```

- PostgreSQL 16이 함께 뜨고 데이터는 `pgdata` 볼륨에 남습니다. `docker-compose.yml`의 `change-me` 비밀번호를 바꾸세요.
- HTTPS는 앞단에 Caddy나 Nginx를 두고, `APP_URL`을 공개 주소로 설정합니다.
- 파일 DB(PGlite)를 운영에서 그대로 쓰려면 `ALLOW_PGLITE_IN_PRODUCTION=1`이 필요하지만 권장하지 않습니다.

## 3. 로컬에서 실제 키로 먼저 돌려 보기

```bash
cp .env.example .env.local        # 키, ADMIN_TOKEN 입력. DATABASE_URL과 SMTP_URL은 비워도 됨
pnpm install && pnpm dev          # PGlite 파일 DB, 메일은 콘솔 출력
pnpm smoke                        # 다른 터미널에서. APP_URL 기본값은 http://localhost:3000
```

개발 모드에서는 인증 메일 링크가 서버 콘솔과 가입 직후 화면에 나오므로 SMTP 없이도 끝까지 써 볼 수 있습니다.

## 4. 배포 뒤 점검표

- [ ] `/api/health`의 `problems`가 비어 있다
- [ ] `pnpm smoke`가 `SMOKE OK`로 끝나고, 분류가 생각 질문은 `think`, 사실 질문은 `direct`로 나왔다
- [ ] 가입 → 인증 메일 수신 → 아이 프로필 → 질문 한 번이 실제로 된다
- [ ] `/admin`에서 호출 비용이 예상 범위(질문 1건 1~2센트)인지 본다
- [ ] 게임을 몇 판 돌려 "맞는 문장"이 정말 맞는지 직접 검수한다
- [ ] `docs/개인정보처리방침.md`의 대괄호를 채우고 `/privacy`에서 확인한다
- [ ] 제미나이·OpenAI 모델 ID가 현재 문서와 맞는지 확인한다 (`/api/health`의 `models`)

## 5. 아직 없는 것

- 로그인·가입 시도 횟수 제한(무차별 대입 방어). 공개 서비스로 가기 전에 필요합니다.
- 오류 모니터링(Sentry 등)과 알림.
- DB 백업 자동화.
