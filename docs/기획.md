# 생각 먼저 AI · 서비스 기획

최종 수정: 2026-10-09 · 상태: MVP 구현 완료, 실제 모델 검증 전

## 1. 왜 만드는가

아이들이 클로드, 제미나이, 챗지피티 같은 AI를 그냥 씁니다. 궁금한 게 생기면 생각하는 과정 없이 바로 묻고, AI가 자신 있게 틀린 말을 할 수 있다는 것(할루시네이션)을 모른 채 답을 받아들입니다.

이 서비스는 AI를 못 쓰게 하는 게 아니라, **묻기 전에 생각하고, 답을 받은 뒤 의심하고 확인하는 습관**을 몸에 배게 하는 것이 목표입니다.

## 2. 대상과 고객

- **사용자**: 초등학교 4~6학년(10~12세) 어린이
- **첫 고객**: 가정의 부모. 학교·학원 대상은 다음 단계
- **사용 전제**: 부모가 로그인한 가정의 공용 기기에서 아이가 사용. 아이 혼자 자기 기기에서 쓰는 흐름은 아직 없음

## 3. 핵심 원칙

1. **AI는 확인해야 하는 상대.** 이것이 정문이다. 아이가 "맞아? 검증해 줘"라고 할 때 같은 AI가 "맞아요"라고 하는 대신, 다른 두 AI에게 묻고 비교하는 버튼을 내민다. 답이 서로 다른 순간을 아이가 직접 본다. 설명보다 체험이 효과적이다.
2. **생각 먼저는 벽이 아니라 장치.** 한 주제의 첫 원리 질문("왜", "어떻게", "~하면 어떻게 될까")에서만 예상을 적어 보게 한다. 아이가 예상을 적었으면 같은 주제에서 한 번 더, 건너뛰었으면 그 주제에서는 더 걸지 않는다. 하루 5회 상한. 매번 강요하면 첫날 떠난다(실제 아이 대화 107개 중 생각 먼저가 맞는 건 8개였다).
3. **대화는 이어진다.** 메시지는 주제(스레드) 안에서 이어지고, 모델은 직전 요약과 최근 턴을 받는다. "그럼", "근데", "정리해 줘", "맞아?"가 전부 통해야 한다.
4. **마음 이야기는 받아 준다.** 자신감·진로·공부 스트레스·장난·고백·화냄은 질문이 아니다. 공감 먼저, 과장된 응원 없이, 어른 권유는 막혔을 때 이유를 붙여 한 번만. 힘든 신호에는 돌봄 안내(어른, 1388)가 먼저다.
5. **감시가 아니라 습관.** 부모는 집계 숫자만 본다. 질문 내용, 개별 게임 결과, 대화 요약은 아이만의 것이다. "부모에게 보여 주기" 같은 공유 장치도 두지 않는다. 단 하나의 예외는 명시적 자해·위험 표현이며, 이때도 내용 없이 "힘든 마음을 표현했다"는 사실만 하루 한 번 알린다. 아이에게 이 약속을 미리 말한다.
6. **부모가 문을 연다.** 부모 계정, 이메일 인증, 만 14세 미만 법정대리인 동의를 거쳐야 아이가 쓸 수 있다.
7. **숙제 답은 통째로 주지 않는다.** 방향만 보여 준다.
8. **호출은 메시지당 1회가 기본.** 원가가 곧 서비스의 생존이다. 분류와 답과 요약을 한 호출로 받고, 비교만 별도로 세며, 문맥은 길이를 고정한다.

## 4. 사용자 흐름

### 4.1 대화 (`/`)

아이의 메시지 하나는 **호출 1회**로 처리된다. 모델이 종류를 정하고, 생각 먼저가 아니면 같은 호출에서 답과 다음 턴용 요약까지 돌려준다.

**메시지 종류 넷**
- **생각 먼저(think)**: 원리·이유·예측 질문이고, 이 주제에서 생각 단계가 허용될 때만. AI가 답 대신 "먼저 생각해 볼 질문"을 던지고 아이는 아는 것과 예상을 적는다. "이번엔 그냥 답 볼래요"로 건너뛸 수 있다(그 주제에서는 다시 걸지 않음). 답을 본 뒤 "한 줄 정리"는 선택.
- **바로 답(direct)**: 사실, 수치, 낱말 뜻, 계산, 이어 묻기의 세부. 한 주제의 첫 바로 답에만 AI가 되묻는 질문 2개와 어림 문제 1개가 붙는다.
- **마음 이야기(talk)**: 자신감·진로·스트레스·장난·고백·화냄·감탄. 짧게 받아 주고, 확신도 배지와 비교 버튼은 붙이지 않는다.
- **작업 지시(task)**: 정리·다시·더 자세히·쉽게·핵심만·검증·채점·계획·시작. 직전 답을 가리키는 표현이 있으면 서버가 직전 답 전문을 함께 보낸다(규칙, 비용 0). "맞아? 검증해 줘"에는 불확실한 부분을 짚고 **비교를 제안**한다(자동 실행은 비용 때문에 하지 않음).

**종류를 가로지르는 것**: 새 주제 판단(newTopic), 받아쓰기 오타·불명확한 뜻은 되묻기(clarify), 부적절한 요청은 안내(safe=false), 힘든 신호는 돌봄 안내(care).

**답 읽기와 비교**: 답에는 AI가 스스로 밝힌 확신도와 "꼭 확인해 봐야 할 부분"이 붙는다. "다른 AI는 뭐라고 할까?"를 누르면 그때 나머지 모델을 호출해 일치/부분 일치/불일치, 서로 달랐던 점, 틀리기 쉬운 주장, 직접 확인하는 방법을 보여 준다. 다른 AI에게는 대화 전체가 아니라 요약만 보낸다.

**스레드와 기억**
- 마지막 메시지 뒤 30분 안이면 하던 주제를 이어 간다. 새로고침해도 "아까 하던 주제에 이어서"로 안내한다. "새 주제" 버튼이나 모델의 새 주제 판단이 스레드를 가른다.
- 모델에 보내는 문맥은 길이가 고정된다: 요약(최대 400자, 모델이 답과 함께 갱신), 최근 3턴(아이 말 원문 + AI 답 첫 문장), 필요할 때만 직전 답 전문(1,500자). 70턴이 되어도 호출당 문맥은 400토큰 안팎이다.
- 요약에는 주제, 확정된 사실, 아이의 목표·헷갈린 것·말투, 어른 권유 여부가 들어가고 개인정보는 넣지 않는다. 스레드 간에 기억을 넘기지 않는다.

**한도**: 하루 "새 주제" 수(기본 10, 부모 조정, 상한 30), 주제당 턴 40, 하루 비교 3회, 하루 생각 단계 5회. 이어 묻기는 새 주제를 소모하지 않는다. 비교가 원가의 대부분이라 따로 센다.

### 4.2 틀린 거 찾기 게임 (`/game`)

주제를 고르면 AI가 5~6문장 설명글을 쓰는데, 그중 정확히 2문장을 일부러 틀리게 쓴다. 실수 종류는 실제 할루시네이션 패턴을 따른다: 숫자 바꿔치기, 날짜·순서 바꿔치기, 이름·장소 바꿔치기, 그럴듯한 가짜 이유. 아이가 틀린 문장을 눌러 고르고 확인하면 찾은 것·놓친 것·맞는 문장을 의심한 것을 색으로 보여 주고, 바르게 고친 내용과 AI의 수법, 오늘의 교훈을 보여 준다. 게임용 글이라는 점을 화면에 명시한다.

### 4.3 내 습관 (`/me`, 아이)

질문 수, 먼저 예상한 비율, 다른 AI와 비교한 비율, AI 답을 의심한 비율, AI끼리 달랐던 질문 수, 게임 판수와 정답률. 그 아래에 자기 질문 전체와 게임 결과. 부모를 언급하는 문구는 최소로. "여기 있는 질문은 나만 볼 수 있어요"와, 힘든 말을 적으면 부모에게 사실만 알린다는 약속 한 줄.

### 4.4 가족 (`/parent`, 부모)

- 아이 프로필 관리: 추가(별명, 학년, 법정대리인 동의 필수), "이 아이로 시작", 삭제
- 아이별 하루 한도: 질문 수·게임 수를 정하고, 오늘 얼마나 썼는지 본다. 비우면 기본값(10·5), 상한은 30·10
- 오늘만 더 열어 주기: 한도를 다 쓴 날 질문 +1/+3, 게임 +1을 그날만 추가. 자정에 사라지고 상한을 넘지 못한다. 아이 화면의 "다 썼어요" 안내에 "부모님께 말해 봐요"를 덧붙임
- 아이별 습관 집계: 아이가 `/me`에서 보는 것과 **같은 컴포넌트**로 같은 숫자를 보여 준다
- 질문 내용, 개별 게임 결과는 어떤 경우에도 보이지 않는다
- 힘든 신호 알림: 아이가 명시적 자해·위험 표현을 적으면 아이에게 돌봄 안내를 보여 주고, 부모에게 하루 한 번 "힘든 마음을 표현했다"는 사실만 메일로 알린다. 내용은 보내지 않는다. 기본 켬, 부모가 끌 수 있다. 간접 표현("사라지고 싶어")은 돌봄 안내만 하고 알리지 않는다.
- 계정 삭제(모든 기록 함께 삭제)
- 부모에게만 보이는 안내: "숫자만 볼 수 있고 질문 내용은 보이지 않는다", "어떤 질문이었는지 묻기보다 가볍게 꺼내 보세요"

### 4.5 계정 (`/signup`, `/login`, `/verify-email`, `/forgot-password`, `/reset-password`)

- 가입 시 인증 메일 발송. **인증을 마쳐야 아이 프로필을 만들 수 있다.** 1분 간격 재전송
- 비밀번호 재설정 메일. 가입 여부를 드러내지 않는다
- 링크 토큰은 해시만 저장, 일회용, 인증 24시간·재설정 1시간 만료. 재설정하면 모든 기기 로그아웃
- 링크를 연 뒤 버튼을 한 번 더 눌러야 처리된다 (메일 스캐너 대비)

### 4.6 안전 필터

- **입력(규칙)**: 아이가 적는 모든 글을 AI에게 보내기 전에 검사. 개인정보, 욕설, 성적 표현, 자해, 약물, 무기 제작, 혐오. 걸리면 AI를 부르지 않고 안내. 자해 표현은 차단이 아니라 돌봄 안내(어른, 1388).
- **출력(규칙 + 자기 검사)**: AI가 만든 글을 아이에게 보여 주기 전에 규칙 검사를 하고, 답을 만든 호출이 같은 호출에서 `okForKid`로 스스로 검사한다(추가 호출 없음). 걸리면 "보여 줄 수 없었어요"로 대체하고 기록한다. `OUTPUT_FILTER=model`이면 Haiku 별도 검사를 한 번 더 돌린다(안전을 비용보다 앞세울 때). 자기 검사는 자기 답을 자기가 보는 것이라 별도 검사보다 약하다는 점은 알고 택한 것이다.
- 생각 단계와 게임 주제의 모델 안전 판정은 그대로.
- 걸린 사례는 `safety_events`에 앞부분 80자만 남기고 `/admin`에서 본다.

## 5-1. 화면 디자인 방향: 대화형, 차분하게

### 원칙

1. **어른이 쓰는 AI 서비스와 같은 모습.** 초등 고학년은 "어린이용"처럼 보이는 것을 싫어한다. 스티커·마스코트·장식·이모지는 쓰지 않는다. 처음 만든 "탐험 노트" 시안(스티커, 마스코트, 공책 질감)은 복잡하고 어려 보여 폐기했다.
2. **화면 하나에 대화 하나.** 질문도 게임도 챗지피티·클로드처럼 대화 타임라인 안에서 진행된다. 아이가 적은 것은 오른쪽 회색 말풍선, AI는 왼쪽에 작은 "AI" 원과 본문. 입력창은 아래에 고정.
3. **색은 의미가 있을 때만.** 흰 바탕, 검정에 가까운 글자색, 회색 보조색, 포인트 색(파랑) 하나. 초록·주황·빨강은 확신도, 일치도, 게임 결과(찾음·놓침·오해), 알림(성공·주의·오류)처럼 뜻이 있는 곳에만 쓴다. 장식용 색은 없다.
4. **상자보다 여백.** 카드 테두리를 겹치지 않는다. 섹션은 제목과 한 줄 설명으로 나누고, 목록은 구분선으로만 가른다. 테두리 상자는 "눌러서 고르는 것"(문장 버튼, 아이 프로필 행)과 표에만 쓴다.
5. **다음 행동은 칩으로.** 예시 질문, 되묻는 질문, 게임 주제, "같은 주제로 한 번 더"처럼 다음에 할 수 있는 일은 모두 같은 모양의 알약 버튼(칩)이다. 누르면 그대로 대화가 이어진다.
6. **부모·운영자 화면도 같은 톤.** 가족, 로그인, 관리자 화면까지 같은 토큰과 부품을 쓴다. 톤이 다른 화면이 하나라도 있으면 "아이용 앱에 어른용 뒷문이 있는" 인상을 준다.

### 화면별

- **질문 (`/`)**: 빈 화면은 "{이름}, 뭐가 궁금해?"와 예시 질문 칩 3개. 생각 단계는 AI 메시지 안의 폼, 답은 AI 메시지, 비교는 버튼을 눌렀을 때 같은 메시지 아래에 펼쳐진다. 되묻는 질문·퍼즐·정리 뒤의 다음 질문은 칩. 입력창은 생각·정리 단계 중에는 잠긴다("위의 단계를 먼저 끝내요").
- **틀린 거 찾기 (`/game`)**: 빈 화면은 "{이름}, 틀린 문장을 찾아볼까?"와 주제 칩 10개. 고른 주제가 아이 말풍선으로 올라가고, AI가 설명글을 보낸다. 문장은 테두리 상자 안의 버튼 목록이고, 고르면 파란 테두리, 결과에서는 초록(찾음)·빨강(놓침)·주황(맞는 문장을 의심)으로 바뀐다. 결과와 "오늘 배운 것"도 AI 메시지. 직접 주제는 아래 입력창에 적는다(Enter로 시작). 진행 중에는 입력창이 잠긴다.
- **내 습관 (`/me`)**: 제목, 통계 타일(흰 바탕·얇은 테두리·큰 숫자), 내 질문 목록(구분선, 일치도는 작은 색 점, 내 예상·정리는 왼쪽 선이 있는 인용 블록), 내 게임 목록. 카드 상자 없음.
- **가족 (`/parent`)**: 제목 "가족". 아이 프로필은 한 줄짜리 행이고 지금 보는 아이만 파란 테두리. 아이가 하나라도 있으면 추가 폼은 "아이 프로필 추가"를 눌러야 펼쳐진다. 습관 집계는 `/me`와 같은 타일 컴포넌트. 하루 한도와 "오늘만 더 열어 주기"는 회색 바탕 상자 하나. 계정 삭제는 맨 아래 조용한 섹션, 버튼은 올렸을 때만 빨갛게.
- **계정 (`/login` 등)**: 좁은 폭(최대 24rem)에 제목, 한 줄 설명, 폼만. 주 버튼은 전체 폭 파랑, 보조 링크는 회색이고 다음 행동으로 이어지는 링크("부모 계정 만들기", "로그인")만 파랑.
- **관리자 (`/admin`)**: 같은 타일과 표. 기간 선택은 알약, 선택된 것만 진한 색. 표 머리글은 회색 작은 글씨로 줄바꿈 없이.

### 토큰과 부품

- **색 토큰** (`src/app/globals.css`의 `@theme`): `bg`(흰색), `surface`/`surface-2`(연회색), `ink`/`ink-soft`(글자), `line`(테두리), `accent`/`accent-deep`/`accent-soft`(파랑), `ok`/`warn`/`bad`와 각각의 `-soft`(의미색과 옅은 배경). 화면 코드에는 Tailwind 기본 색 이름(stone, amber 등)을 쓰지 않는다. 나중에 다크 모드나 색 조정이 필요하면 토큰만 바꾼다.
- **서체**: Pretendard Variable. 외부 CDN 대신 `public/fonts/pretendard/`에 동적 서브셋(92개 파일, 약 3MB)을 자체 호스팅해 화면에 쓰인 글자 범위만 내려받는다(SIL OFL). 없으면 기기 기본 한글 서체. 굵기는 regular와 semibold 둘만 쓰고, 강조는 굵기보다 크기와 색으로.
- **글자 크기**: 본문 15px, 보조 13px, 메타 12px, 제목 2xl(semibold, 자간 좁게), 섹션 제목 base(semibold).
- **공용 부품**:
  - `src/components/chat.tsx`: `AiMsg`, `UserMsg`, `Chip`, `Composer`(하단 고정 입력창, Enter 보내기, Shift+Enter 줄바꿈). 질문과 게임이 같은 것을 쓴다.
  - `src/components/ui.tsx`: `Button`/`buttonClass`(primary·secondary·ghost·danger, 서버 컴포넌트의 폼 버튼과 링크에도 같은 클래스), `inputClass`, `Field`, `TextArea`, `Notice`(info·ok·warn·bad), `FormNotice`(서버 액션 결과 표시), `ConfidenceBadge`, `AgreementBanner`, `Spinner`.
  - `src/components/AuthShell.tsx`: 계정 화면 공용 틀. `HabitStats.tsx`의 통계 타일은 아이와 부모가 공유.
- **모서리**: 말풍선·타일·상자 2xl(16px), 버튼·입력칸 xl(12px), 칩과 알약은 full.
- **기준 폭**: 모든 화면을 390px(폰)에서 먼저 확인한다. 본문 최대 폭은 3xl(48rem), 계정 화면은 sm(24rem).

### 하지 않는 것

- 이모지, 일러스트, 마스코트, 배경 질감, 그림자(입력창의 아주 옅은 그림자 하나 제외)
- "잘했어요!" 류의 과한 칭찬 배너, 포인트·배지·레벨 같은 게임화 장치
- 부모가 보고 있다는 느낌을 주는 문구나 아이콘 (아이 화면에 부모 언급 금지)
- 화면마다 다른 색이나 서체

## 6. 기술 구조

- **앱**: Next.js 16(App Router, Cache Components), TypeScript, Tailwind
- **AI**: Vercel AI SDK로 세 제공사를 한 인터페이스로 호출. 메시지 하나는 `respond` 호출 1회로 종류·답·요약을 받고(클로드 우선), 생각 먼저일 때만 예상 뒤 답 호출이 하나 더 간다. 비교 버튼을 눌렀을 때 나머지 모델과 판정을 부른다. 답변 모델은 비용 최우선으로 각 회사의 가장 가벼운 모델 `claude-haiku-5-5`, `gemini-flash-latest`, `gpt-5.4-nano`(환경변수로 변경). 생각 단계·비교 판정·반성·게임 문제 생성도 `claude-haiku-5-5`가 맡고, Claude 키가 없으면 설정된 다른 제공사로 대체. Claude 답변은 사고 강도 `low`. 모든 호출은 구조화 출력(스키마)으로 받는다
- **DB**: Drizzle ORM, PostgreSQL 스키마 하나. 스레드(`threads`)가 요약과 생각 단계 상태를 들고, 질문 기록이 스레드에 매달린다. `DATABASE_URL`이 있으면 Postgres, 없으면 파일 기반 PGlite. 마이그레이션은 시작 시 자동 적용
- **인증**: 외부 라이브러리 없이 scrypt + DB 세션
- **메일**: nodemailer(SMTP). 설정이 없으면 링크를 콘솔에 출력
- **운영**: 모든 AI 호출의 토큰 사용량을 `ai_usage`에 기록. `/admin`(ADMIN_TOKEN)에서 현황과 기간별 비용(총액, 질문 1건당, 게임 1판당, 용도·모델별, 날짜별)을 보고, `pnpm usage`로 터미널에서도 본다. 요금표는 `src/lib/pricing.ts`
- **개발**: `MOCK_AI=1`로 키 없이 실행. Playwright 자동 테스트로 전체 흐름 검증

## 8. 남은 과제

**검증**
- 실제 초등학생 대화 분석(`docs/실사용-대화-분석.md`)을 바탕으로 스레드·종류 넷·호출 합치기·스레드 단위 한도·검증 시 비교 제안·되묻기를 구현했다. 실제 키로 분류 경향과 요약 품질, 되묻기가 과하지 않은지 확인하는 것이 다음이다. 생각 단계 하루 상한과 턴 상한 값은 실측 뒤 조정
- 실제 키로 세 모델의 답변 톤, 비교 판정 품질, 게임의 "맞는 문장"이 정말 맞는지 직접 확인
- 질문 분류(바로 답 vs 생각 먼저)가 실제 아이 질문에서 어떻게 나뉘는지, 추론 문제의 난이도가 적절한지 확인
- 제미나이·챗지피티 모델 ID를 공식 문서로 확정
- SMTP 실제 발송 테스트

**안전·정책**
- 안전 필터 규칙을 실제 아이 입력으로 다듬기 (오탐·미탐 확인, `/admin` 사례 활용)
- Anthropic, Google, OpenAI의 미성년자 대상 서비스 조건 검토
- 개인정보 처리방침(`docs/개인정보처리방침.md`)의 대괄호 항목 채우기와 전문가 검토. 특히 AI 제공사별 API 데이터 보존·학습 미사용 정책 확인

**제품**
- 아이 혼자 자기 기기에서 쓰는 흐름 (아이용 간단 로그인)
- 비용 관리: 질문 1건에 모델 호출 2~3번(비교 시 +3), 가벼운 모델 기준 1센트 안팎. 아이당 하루 한도 있음. 실측은 `/admin`에서
- 요금제: 무료 체험(하루 3건) + 월 구독(아이 2명, 하루 10~15건) 가능성 검토
- 부모 화면의 게임 집계 타일 2개를 남길지 여부
- 학교·학원용(교사 계정, 학급 단위) 확장 여부

**디자인**
- 실제 초등 고학년 아이 몇 명에게 화면을 보여 주고 "어린이용 같다"는 느낌이 없는지, 생각 단계가 귀찮지 않은지 확인
- 다크 모드 (토큰만 바꾸면 되도록 준비됨, 아직 정의 안 함)
- 데스크톱에서 대화 폭(48rem)이 적절한지, 게임 문장 버튼이 넓은 화면에서 너무 길어지지 않는지 확인
- 질문 뒤 상단 "오늘 남은 질문" 칩이 서버 값이라 바로 갱신되지 않는 문제 (입력창 안내문만 즉시 줄어듦)

**운영**
- 배포: `docs/배포.md`(Vercel 또는 Docker Compose), `/api/health`, `pnpm smoke`로 점검. Docker 이미지 빌드는 아직 실제로 돌려 보지 않음
- 백업을 외부 저장소(S3 등)에도 올리기. 지금은 GitHub 아티팩트 30일 + Docker 볼륨
