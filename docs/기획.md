# 생각 먼저 AI · 서비스 기획

최종 수정: 2026-10-09 · 상태: MVP 구현 완료, 실제 모델 검증 전

## 1. 왜 만드는가

아이들이 클로드, 제미나이, 챗지피티 같은 AI를 그냥 씁니다. 궁금한 게 생기면 생각하는 과정 없이 바로 묻고, AI가 자신 있게 틀린 말을 할 수 있다는 것(할루시네이션)을 모른 채 답을 받아들입니다.

이 서비스는 AI를 못 쓰게 하는 게 아니라, **묻기 전에 생각하고, 답을 받은 뒤 의심하고 확인하는 습관**을 몸에 배게 하는 것이 목표입니다.

## 2. 대상과 고객

- **사용자**: 초등학교 4~6학년(10~12세) 어린이
- **첫 고객**: 가정의 부모. 학교·학원 대상은 다음 단계
- **사용 전제**: 부모가 로그인한 가정의 공용 기기에서 아이가 사용. 아이 혼자 자기 기기에서 쓰는 흐름은 아직 없음

## 3. 핵심 원칙

1. **생각이 필요한 질문만 생각 먼저.** "왜", "어떻게", "~하면 어떻게 될까"처럼 아이가 스스로 추론할 수 있는 질문은 예상을 적어야 답을 볼 수 있다. 단순 사실(거리, 날짜, 이름, 낱말 뜻, 환산)은 바로 답한다. 매번 생각을 강요하면 귀찮아서 안 쓰게 된다.
1-1. **바로 답한 뒤엔 AI가 되묻는다.** 답과 함께 이어지는 질문("그럼 해까지는 얼마나 멀까?")과 그 사실로 추론해 보는 문제("시속 100km로 달까지 가면 며칠?")를 던진다. 답을 받는 순간을 생각의 출발점으로 바꾼다.
2. **AI는 확인해야 하는 상대.** 세 모델에 같은 질문을 보내고, 답이 서로 다를 때를 아이에게 직접 보여 준다. 설명보다 체험이 효과적이다.
3. **감시가 아니라 습관.** 부모는 집계 숫자만 본다. 질문 내용과 개별 게임 결과는 아이만 본다. "부모에게 보여 주기" 같은 공유 선택 장치도 두지 않는다. 그 장치 자체가 "보고 있다"는 신호가 되기 때문이다.
4. **부모가 문을 연다.** 부모 계정, 이메일 인증, 만 14세 미만 법정대리인 동의를 거쳐야 아이가 쓸 수 있다.
5. **숙제 답은 통째로 주지 않는다.** 방향만 보여 준다.

## 4. 사용자 흐름

### 4.1 질문하기 (`/`)

0. **분류** – 질문을 받으면 AI가 먼저 종류를 나눈다. 단순 사실이면 "바로 답하는 질문", 추론할 여지가 있으면 "생각이 필요한 질문". 애매하면 바로 답하는 쪽으로.

**바로 답하는 질문**: 생각 단계 없이 곧장 3단계(답 읽기, 확신도, 다른 AI 비교)로 간다. 그 아래에 두 가지가 붙는다.
- 🙋 **AI가 되묻는 질문** 2~3개. "먼저 머릿속으로 찍어 보고 누르라"고 하며, 누르면 그 질문으로 이어진다.
- 🧩 **그 사실로 풀어 보는 문제** 1~2개. 초등 고학년이 곱셈·나눗셈으로 어림할 수 있는 수준. 힌트가 있고, 자기 답을 적어야 풀이가 열린다. "딱 맞지 않아도 괜찮다"고 말해 준다.

**생각이 필요한 질문**: 아래 1~5단계.

1. **질문** – 궁금한 것을 적는다.
2. **생각 먼저** – AI가 답 대신 "먼저 생각해 볼 질문"을 던진다. 아이는 아는 것과 **예상**을 적어야 넘어간다. 힌트 버튼이 있다. 부적절한 질문은 여기서 부드럽게 돌려보낸다.
3. **답 읽기** – 답 하나를 먼저 보여 준다. AI가 스스로 밝힌 확신도(꽤/조금/확실하지 않음)와 "꼭 확인해 봐야 할 부분"이 붙는다.
4. **다른 AI는 뭐라고 할까?** – 버튼을 누르면 나머지 모델의 답과 비교 결과가 나온다. 🟢 일치 / 🟡 부분 일치 / 🔴 불일치, 서로 달랐던 점, 틀리기 쉬운 주장(숫자·날짜·이름), 직접 확인하는 방법(교과서, 백과사전, 선생님·부모님).
5. **한 줄 정리** – 새로 알게 된 것을 적고, "정말일까? 싶은 부분이 있었다"를 표시할 수 있다. AI는 과정을 칭찬하고, 예상과 답을 비교하고, 확인 방법과 다음 질문을 제안한다.

### 4.2 틀린 거 찾기 게임 (`/game`)

주제를 고르면 AI가 5~6문장 설명글을 쓰는데, 그중 정확히 2문장을 일부러 틀리게 쓴다. 실수 종류는 실제 할루시네이션 패턴을 따른다: 숫자 바꿔치기, 날짜·순서 바꿔치기, 이름·장소 바꿔치기, 그럴듯한 가짜 이유. 아이가 틀린 문장을 눌러 고르고 확인하면 찾은 것·놓친 것·맞는 문장을 의심한 것을 색으로 보여 주고, 바르게 고친 내용과 AI의 수법, 오늘의 교훈을 보여 준다. 게임용 글이라는 점을 화면에 명시한다.

### 4.3 내 습관 (`/me`, 아이)

질문 수, 먼저 예상한 비율, 다른 AI와 비교한 비율, AI 답을 의심한 비율, AI끼리 달랐던 질문 수, 게임 판수와 정답률. 그 아래에 자기 질문 전체와 게임 결과. 부모를 언급하는 문구는 넣지 않는다. "여기 있는 질문은 나만 볼 수 있어요" 한 줄만.

### 4.4 우리 가족 기록 (`/parent`, 부모)

- 아이 프로필 관리: 추가(별명, 학년, 법정대리인 동의 필수), "이 아이로 시작", 삭제
- 아이별 습관 집계: 아이가 `/me`에서 보는 것과 **같은 컴포넌트**로 같은 숫자를 보여 준다
- 질문 내용, 개별 게임 결과는 어떤 경우에도 보이지 않는다
- 계정 삭제(모든 기록 함께 삭제)
- 부모에게만 보이는 안내: "숫자만 볼 수 있고 질문 내용은 보이지 않는다", "어떤 질문이었는지 묻기보다 가볍게 꺼내 보세요"

### 4.5 계정 (`/signup`, `/login`, `/verify-email`, `/forgot-password`, `/reset-password`)

- 가입 시 인증 메일 발송. **인증을 마쳐야 아이 프로필을 만들 수 있다.** 1분 간격 재전송
- 비밀번호 재설정 메일. 가입 여부를 드러내지 않는다
- 링크 토큰은 해시만 저장, 일회용, 인증 24시간·재설정 1시간 만료. 재설정하면 모든 기기 로그아웃
- 링크를 연 뒤 버튼을 한 번 더 눌러야 처리된다 (메일 스캐너 대비)

## 5. 데이터와 개인정보

| 테이블 | 내용 |
| --- | --- |
| `parents` | 이메일, 이름, 비밀번호 해시(scrypt), 이메일 인증 시각 |
| `auth_sessions` | 로그인 세션 토큰(httpOnly 쿠키), 만료 |
| `email_tokens` | 인증·재설정 토큰 해시, 용도, 만료, 사용 시각 |
| `children` | 부모, 별명, 학년, 동의 버전·시각 |
| `question_logs` | 아이, 질문, 종류(바로 답/생각 먼저), 주제, 아는 것, 예상, 힌트 사용, 일치도, 비교 여부, 정리, 의심 표시, 세 모델 답변과 판정(JSON) |
| `game_results` | 아이, 주제, 틀린 문장 수, 찾은 수, 오답 수, 문제(JSON) |

- 수집 항목과 목적은 가입 화면과 아이 프로필 생성 화면에 적혀 있다
- 질문 내용은 답변 생성을 위해 AI 제공사(Anthropic, Google, OpenAI)에 전송된다
- 프로필·계정 삭제 시 관련 기록이 모두 삭제된다(cascade)

## 6. 기술 구조

- **앱**: Next.js 16(App Router, Cache Components), TypeScript, Tailwind
- **AI**: Vercel AI SDK로 세 제공사를 한 인터페이스로 호출. 답변 모델은 `claude-opus-5-5`, `gemini-flash-latest`, `gpt-5.5`(환경변수로 변경). 생각 단계·비교 판정·반성·게임 문제 생성은 `claude-sonnet-5-5`가 맡고, Claude 키가 없으면 설정된 다른 제공사로 대체. 모든 호출은 구조화 출력(스키마)으로 받는다
- **DB**: Drizzle ORM, PostgreSQL 스키마 하나. `DATABASE_URL`이 있으면 Postgres, 없으면 파일 기반 PGlite. 마이그레이션은 시작 시 자동 적용
- **인증**: 외부 라이브러리 없이 scrypt + DB 세션
- **메일**: nodemailer(SMTP). 설정이 없으면 링크를 콘솔에 출력
- **개발**: `MOCK_AI=1`로 키 없이 실행. Playwright 자동 테스트로 전체 흐름 검증

## 8. 남은 과제

**검증**
- 실제 키로 세 모델의 답변 톤, 비교 판정 품질, 게임의 "맞는 문장"이 정말 맞는지 직접 확인
- 질문 분류(바로 답 vs 생각 먼저)가 실제 아이 질문에서 어떻게 나뉘는지, 추론 문제의 난이도가 적절한지 확인
- 제미나이·챗지피티 모델 ID를 공식 문서로 확정
- SMTP 실제 발송 테스트

**안전·정책**
- 입력·출력 양쪽의 별도 안전 필터 (지금은 시스템 프롬프트와 생각 단계의 안전 판정에만 의존)
- Anthropic, Google, OpenAI의 미성년자 대상 서비스 조건 검토
- 개인정보 처리방침 문서

**제품**
- 아이 혼자 자기 기기에서 쓰는 흐름 (아이용 간단 로그인)
- 비용 관리: 질문 하나에 모델 호출 4~5번. 하루 질문 수 제한 또는 요금제
- 부모 화면의 게임 집계 타일 2개를 남길지 여부
- 학교·학원용(교사 계정, 학급 단위) 확장 여부

**운영**
- 배포 환경(PostgreSQL, SMTP, APP_URL) 구성
- 로그·모니터링
